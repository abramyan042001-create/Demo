# Корочки.есть — подробный учебный проект для ДЭ

Готовый локальный портал записи на курсы по присланной инструкции «Решение ДЭ Корочки есть». Python + Django + SQLite. Написанный для проекта код сопровождается русскими пояснениями к каждой непустой строке: что делает строка, откуда берутся данные и зачем действие требуется.

**Начните с [START_HERE.html](START_HERE.html): скачайте весь проект и откройте этот файл в браузере. Он содержит пособие и работает без сервера и интернета.** В GitHub HTML показывается как исходник, поэтому для чтения его нужно скачать. Все тексты также лежат в docs/ в Markdown.

## Быстрый запуск без интернета

Нужен заранее установленный Python 3.10+; для подготовки рекомендуем Python 3.12 со стандартными модулями pip, venv и ensurepip.

1. Распакуйте полный `Demo_offline.zip` в обычную папку. Не запускайте изнутри ZIP.
2. Откройте терминал в папке, в которой находятся `manage.py` и `bootstrap.py`.
3. Выполните одну команду ниже.
4. При первом запуске введите пароль администратора **из вашего задания**. Символы ввода не показываются — это нормально. Логин администратора: `Admin`.
5. Откройте `http://127.0.0.1:8000/` в браузере. Терминал должен оставаться открытым. Остановка — Ctrl+C.

```bash
# Создать окружение, установить локальные пакеты, подготовить БД и запустить сервер.
python bootstrap.py
```

В Windows, если `python` не найден, используйте `py -3 bootstrap.py`. Подробности: [START_WINDOWS.md](docs/START_WINDOWS.md).

**GitHub-копия не включает бинарные wheel-пакеты.** Если скачали только её, сначала при наличии интернета выполните `python bootstrap.py --prepare`. Полный офлайн-архив уже содержит эти пакеты. Обычный запуск использует `pip --no-index`: скачивание из сети отключено.

## Функции и страницы

| Адрес | Назначение | Доступ |
| --- | --- | --- |
| `/register/` | Регистрация: логин, ФИО, телефон, email, пароль и повтор | Гость |
| `/login/` | Проверка логина/пароля и создание сессии | Гость |
| `/applications/` | Только собственные заявки; отзыв после завершения | Пользователь |
| `/applications/new/` | Выбор курса, дата ДД.ММ.ГГГГ, оплата | Пользователь |
| `/admin/` | Все заявки, фильтр, страницы по 5 записей, смена статуса | `is_staff=True` |

Курсов ровно три, как в инструкции. Статусы идут по порядку: «Новая» → «Идет обучение» → «Обучение завершено». Пароли хешируются стандартными механизмами Django. Административная роль хранится в БД. Все POST-формы защищены CSRF. Автоэкранирование HTML включено. Секретный ключ автоматически создаётся на компьютере и исключён из Git; пароль администратора публично не хранится.

## Структура

- `config/` — настройки Django и главная маршрутизация.
- `portal/models.py` — таблицы, поля, связи, индексы, ограничения БД.
- `portal/validators.py` — единые серверные регулярные выражения.
- `portal/forms.py` — формы и правила проверки пользовательского ввода.
- `portal/views.py` — обработчики запросов и проверка прав.
- `portal/urls.py` — адреса и имена маршрутов.
- `portal/migrations/` — воспроизводимая схема БД, с пояснениями строк.
- `portal/management/commands/seed.py` — создание справочника и администратора.
- `templates/` — HTML с построчными комментариями Django `{# ... #}`.
- `static/` — локальные CSS, JavaScript и SVG с построчными комментариями.
- `tools/` — экспорт схемы и дополнительная проверка слайдера.
- `offline_packages/` — памятка и контрольные суммы; в полном ZIP также wheel-пакеты.

Структура адаптирована к Django: это соответствует требованию полного стека и ООП; имена backend/frontend в исходной инструкции даны как пример, а не обязательный каркас.

## Проверка

```bash
# Проверить настройки проекта; команды выполнять Python из активного окружения.
python manage.py check
# Проверить полный набор серверных сценариев в отдельной тестовой БД.
python manage.py test
# Убедиться, что модели и сохранённая миграция согласованы.
python manage.py makemigrations --check --dry-run
# Пересоздать пять отдельных мобильных HTML по общим шаблонам.
python manage.py export_mobile
# Дополнительно: проверить JavaScript, если Node.js установлен; самому порталу он не нужен.
node tools/test_slider.cjs
```

## Ограничения исходных материалов

В присланном 7z лежит **только HTML-пособие**, а не полный официальный комплект КОД. Упомянутых в нём фотографий, логотипов и дополнительных вариантов задания нет. Для слайдера созданы локальные SVG; замена на выданные фотографии описана в [MODULE_2.md](docs/MODULE_2.md).

ER автоматически построена по фактической структуре SQLite через PRAGMA и Graphviz. Если эксперт требует именно экспорт из DBeaver/Workbench/pgAdmin, на площадке откройте свою БД в выданной программе и сохраните дополнительный экспорт; последовательность есть в пособии. Выбор SQLite тоже нужно сверить с разрешённой на площадке СУБД.

Это подготовительная работа. Разрешение использовать готовые исходники и пособие на самом экзамене определяет площадка. В день экзамена соблюдайте выданный порядок самостоятельного выполнения. История этого репозитория отражает этапы подготовки, а не прохождение экзамена.
