# Практика: от маленького примера к самостоятельной работе

Работай в отдельной тренировочной папке или ветке, чтобы можно было сравнивать с образцом. Сначала попробуй решить без подглядывания, затем сверяйся. Если читаешь без компьютера, записывай ответ на бумаге и объясняй, что попадёт в каждую переменную.

## 1. Модели

1. Напиши Course с одним полем title. Объясни max_length и unique.
2. Добавь __str__. Предскажи, что изменится в выпадающем списке.
3. Напиши Application с course, user и start_date. Нарисуй связи.
4. Добавь статус с default new. Почему форму не нужно просить прислать начальный статус?
5. Не глядя в образец, напиши две команды создания и применения миграции.

## 2. Форма и сохранение

6. Напиши ModelForm, принимающую только курс и дату. Почему user не включён?
7. Напиши view: GET → пустая форма; POST → проверка. Сначала просто покажи данные, потом добавь сохранение.
8. Добавь commit=False и владельца из request.user. Объясни, в какой момент объект попадает в БД.
9. Сделай redirect после сохранения. Что произойдёт при обновлении следующей страницы?
10. Выведи ошибки под полями, а не одним общим сообщением сверху.

## 3. Личный кабинет

11. Выведи только заявки вошедшего пользователя. Почему objects.all здесь неправильно?
12. Напиши цикл for в HTML и ветку empty для пустого списка.
13. Добавь отображение даты ДД.ММ.ГГГГ и русской подписи статуса.
14. Сделай форму отзыва только для completed. Затем объясни, почему ту же проверку нужно добавить во view.
15. Попробуй получить заявку по чужому id. Напиши условие, которое запретит это.

## 4. Вход и администратор

16. Подключи AuthenticationForm. Найди, где проверяется пароль и где создаётся сессия.
17. Напиши отдельный if для is_staff после входа.
18. Закрой панель и обработчик статуса обычному пользователю. Почему недостаточно скрыть ссылку?
19. Сделай ChoiceField для статуса. Что произойдёт с присланным значением hacked?
20. Добавь фильтр GET и Paginator по пять записей. Сохрани фильтр в ссылке на следующую страницу.

## 5. Маленькое изменение требования

Добавь к заявке необязательное поле «Комментарий» до 300 символов. Самостоятельно реши:

- Что добавить в Application?
- Что добавить в ApplicationForm.Meta.fields?
- Нужно ли менять универсальный шаблон form.html, который уже перебирает поля?
- Как вывести комментарий в кабинете?
- Какие команды нужны для БД?

**Подсказка после попытки:** модель и форма меняются, универсальная форма сама покажет новое поле; для отображения в карточке потребуется отдельная строка HTML. После изменения модели нужна миграция. Владелец и статус остаются серверными полями.

## 6. Вопросы для самопроверки

| Вопрос | Короткий ответ для проверки после своей попытки |
| --- | --- |
| GET и POST чем отличаются? | GET просматривает, POST передаёт действие с данными |
| Где лежат сырые поля отправленной формы? | request.POST |
| Где лежат проверенные значения? | form.cleaned_data после is_valid |
| Что делает save(commit=False)? | Возвращает объект без записи в БД |
| Что такое request.user? | Пользователь, определённый Django по сессии |
| Почему пароль нельзя присваивать напрямую? | Нужен хеш: UserCreationForm, create_user или set_password |
| Почему Admin из пяти букв входит? | Минимум шесть применяется к регистрации, а не ко входу существующего аккаунта |
| Что делает login_required? | Не допускает гостя до личной функции |
| Что делает csrf_token? | Добавляет защитный токен формы, проверяемый сервером |
| Как не показать чужие заявки? | Отфильтровать по user=request.user до передачи в HTML |
| Как защитить отдельную заявку? | Получать её одновременно по pk и владельцу |
| Что даёт is_staff? | В этой работе это роль администратора из БД |
| Почему проверка роли нужна во view? | Ссылку можно скрыть, но прямой HTTP-запрос всё равно возможен |
| Как получить русскую подпись choices? | get_имя_поля_display |
| Как сохранить сообщение после redirect? | messages.success или messages.error |
| Что нужно выполнить после изменения модели? | makemigrations, затем migrate |
| Что из проекта не нужно писать вручную? | Сгенерированные миграции, код Django и служебный каркас |

## 7. Пробная самостоятельная сборка

Закрой готовые models/forms/views. На чистом листе сначала напиши названия трёх моделей и семи пользовательских действий. Потом реализуй их по одному. Не начинай с CSS. Для каждого действия проговори: кто имеет доступ, откуда приходят данные, что проверяем, что сохраняем и какой ответ возвращаем.

Если не можешь вспомнить конкретный параметр Django, сначала объясни словами нужное действие. Затем найди одну соответствующую строку в образце и перепиши её осознанно, а не копируй всю функцию.
