# Запуск в Windows: от скачанного архива до страницы

## 1. Что подготовить заранее

Установите Python, рекомендуем 3.12. Во время установки включите pip и Add Python to PATH. Нужен обычный локальный браузер. VS Code удобен для чтения кода, но портал работает и без него. Git нужен для истории изменений и отправки работы. Node.js и Graphviz не нужны для запуска портала: они используются только дополнительными инструментами проверки и экспорта.

Перед экзаменом уточните доступную версию Python, наличие Django в общей офлайн-папке, разрешённую СУБД и правила переноса материалов. Если разрешён только PostgreSQL/MySQL, нельзя просто считать этот SQLite-проект полностью соответствующим: сначала замените настройки БД, заранее подготовьте драйвер и проверьте миграции в выданной СУБД.

Проверьте Python в терминале:

```powershell
# Показывает версию Python через стандартный Windows launcher.
py -3 --version
# Показывает версию pip для того же Python, а не случайной другой установки.
py -3 -m pip --version
```

## 2. Где должна быть папка проекта

Распакуйте `Demo_offline.zip`, например в `C:\Study\Demo`. В этой папке непосредственно должны находиться manage.py, bootstrap.py, README.md, config/, portal/, templates/ и offline_packages/. Если появилась дополнительная вложенная папка Demo, перейдите именно в неё.

Не открывайте проект внутри окна архиватора: относительные пути и сохранение SQLite будут работать неправильно. Не переносите готовую `.venv` между компьютерами: окружение содержит пути конкретной установки Python. Переносите исходники и wheel-пакеты; новое окружение создаст bootstrap.

## 3. Самый короткий запуск

В VS Code: «Файл → Открыть папку» и выберите Demo. Затем «Терминал → Новый терминал». В проводнике Windows можно открыть папку и в адресной строке написать `powershell`.

```powershell
# Перейти в распакованную папку; кавычки нужны, если путь содержит пробелы.
cd C:\Study\Demo
# Установить всё из локальной папки и запустить сервер.
py -3 bootstrap.py
```

Первый запуск создаёт `.venv`, ставит четыре пакета из offline_packages, создаёт SQLite, запрашивает пароль нового администратора, проверяет настройки и включает сервер. Введите пароль, указанный в экзаменационном условии, и нажмите Enter. Ввод не отображается даже звёздочками. При повторном запуске seed не запрашивает и не сбрасывает существующий пароль.

Откройте в браузере `http://127.0.0.1:8000/`. Адрес 127.0.0.1 означает этот же компьютер: интернет не нужен. Оставьте терминал открытым, пока работаете с порталом. Ctrl+C останавливает сервер.

## 4. Ручной запуск, чтобы понимать каждый шаг

Команды ниже выполняются последовательно из папки Demo в PowerShell. Путь `.venv\Scripts\python.exe` явно выбирает нужный интерпретатор, поэтому активация окружения не обязательна.

```powershell
# Создать изолированное окружение в папке .venv; файлы проекта не меняются.
py -3 -m venv .venv
# Установить фиксированные версии исключительно из локальных wheel-пакетов; --no-index отключает сеть.
.\.venv\Scripts\python.exe -m pip install --no-index --find-links offline_packages -r requirements-offline.txt
# Создать таблицы по сохранённым миграциям; эту команду безопасно выполнять повторно.
.\.venv\Scripts\python.exe manage.py migrate
# Добавить три курса и администратора; пароль нового аккаунта ввести по условию задания.
.\.venv\Scripts\python.exe manage.py seed
# Проверить настройки, модели и конфигурацию.
.\.venv\Scripts\python.exe manage.py check
# Запустить локальный сервер; после этой строки терминал занят до Ctrl+C.
.\.venv\Scripts\python.exe manage.py runserver
```

## 5. Git Bash

В проводнике откройте папку Demo и выберите Git Bash Here. Если такого пункта нет, откройте Git Bash отдельно и перейдите по пути:

```bash
# В Git Bash диск C записывается как /c; кавычки сохраняют пробелы в пути.
cd /c/Study/Demo
# Windows launcher доступен и из Git Bash, если установлен Python.
py -3 bootstrap.py
```

Для ручных команд в Git Bash можно использовать `.venv/Scripts/python.exe manage.py runserver`. Команда `source .venv/Scripts/activate` делает `python` из окружения доступным без полного пути, но bootstrap и явный путь работают без активации.

## 6. Если скачали только GitHub

На странице репозитория выберите Code → Download ZIP и распакуйте. GitHub ZIP содержит исходники, инструкции и макеты, но не бинарные wheel-пакеты. Пока интернет доступен, выполните:

```powershell
# Скачать зависимости в offline_packages; это подготовительный онлайн-режим.
py -3 bootstrap.py --prepare
# После скачивания проверить обычный запуск; он устанавливает пакеты без обращения к сети.
py -3 bootstrap.py
```

Лучше один раз выключить интернет и убедиться, что повторный запуск работает. Не удаляйте wheel-файлы. Сам Python должен быть установлен до отключения интернета.

## 7. Частые ошибки

| Сообщение или ситуация | Причина и действие |
| --- | --- |
| python не найден / открывается Microsoft Store | Используйте `py -3`; если launcher тоже отсутствует, установите Python заранее |
| can't open file manage.py | Терминал открыт не в той папке; выполните `dir` и перейдите к manage.py |
| No module named django | Команда запущена системным Python; используйте `.venv\Scripts\python.exe` или bootstrap |
| Нет wheel-пакетов | Скачан только GitHub ZIP; нужен полный офлайн-архив или предварительный `bootstrap.py --prepare` |
| No matching distribution found | Сверьте версию Python и наличие всех четырёх wheel-файлов; для этого проекта нужен Python 3.10+ |
| no such table: portal_user | Не выполнено `manage.py migrate` тем же окружением и в том же проекте |
| Курс не выбирается / список пустой | Выполните `manage.py seed` после migrate |
| CSRF verification failed | Откройте форму заново и отправьте с неё; не отключайте CsrfViewMiddleware |
| Нажимаю ссылки в mobile/, данные не сохраняются | mobile/ — отдельные статические макеты; рабочий сайт находится по адресу локального сервера |
| Пароль при seed не печатается | Это скрытый ввод getpass; наберите пароль и нажмите Enter |
| Admin не входит после повторного seed | Существующий пароль не сбрасывается; используйте ранее заданный или смените его командой ниже |
| Port is already in use | Старый сервер ещё работает: остановите Ctrl+C или запустите runserver 8001 |
| В браузере Connection refused | Сервер не запущен, завершился с ошибкой или открыт другой порт |
| В PowerShell запрещено выполнение Activate.ps1 | Активация не нужна: используйте полный путь `.venv\Scripts\python.exe` |

Если забыли собственный локальный пароль администратора:

```powershell
# Запросить новый пароль интерактивно; изменяется только указанный локальный пользователь.
.\.venv\Scripts\python.exe manage.py changepassword Admin
```

Не удаляйте db.sqlite3 ради исправления обычной ошибки: в ней находятся все введённые пользователи, заявки и отзывы. Копия проекта из архива создаёт новую чистую БД при первом запуске.
